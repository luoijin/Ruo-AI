# Rust Core

- **Purpose:** Define the headless Rust core: crate layout, UniFFI interface, threading, errors, build and testing.
- **Audience:** Rust and Android engineers, agents.
- **Status:** Draft
- **Last updated:** 2026-11-25
- **Related docs:** [ANDROID_CLIENT](ANDROID_CLIENT.md), [API_CONTRACT](API_CONTRACT.md), [DATA_MODEL](DATA_MODEL.md), [../skills.md](../skills.md), [ADR-0002](decisions/ADR-0002-rust-uniffi-client-core.md)

## Responsibilities [v1]
SSE client with reconnect and cancel · resumable chunked uploader and hashing · SQLCipher store with migrations · outbox queue · client-side validation. **Headless:** never touches Android lifecycle, content URIs or Compose state. Kotlin passes plain file paths and primitives.

Justification: reliability on the hardest client problems and a skills showcase. Not cross-platform reuse.

## Crate layout
See [FOLDER_STRUCTURE](FOLDER_STRUCTURE.md): `ruo_core` (cdylib, plus lib for tests) with modules `db`, `net`, `upload`, `outbox`, `validate`.

## UniFFI interface
The Gate 2 spike used UniFFI 0.32.2 proc-macro mode; syntax follows the [0.32 proc-macro guide](https://mozilla.github.io/uniffi-rs/0.32/proc_macro/index.html). The core is an *object with a constructor*, not a trait. Phase 1 interface version 1 is recorded below; additions must be additive, and breaking changes require a separately versioned interface.
```rust
#[derive(uniffi::Record)]
pub struct LocalMessage {
    pub id: String, pub conversation_id: String,
    pub role: String,        // "user" | "assistant"
    pub content_md: String,
    pub status: String,      // "queued" | "streaming" | "sent" | "failed"
    pub citations_json: Option<String>,
    pub created_at_ms: i64,
}

#[uniffi::export(foreign)]
pub trait StreamListener: Send + Sync {
    fn on_meta(&self, message_id: String, detected_language: Option<String>, fallback: bool);
    fn on_delta(&self, message_id: String, text: String);
    fn on_citation(&self, message_id: String, attachment_id: String, snippet: Option<String>);
    fn on_complete(&self, message_id: String);
    fn on_error(&self, message_id: String, code: String, retryable: bool);
}

#[uniffi::export(foreign)]
pub trait DraftReadListener: Send + Sync {
    fn on_draft_read(&self, conversation_id: String, text: String);
}

#[derive(uniffi::Object)]
pub struct RuoCore { /* db handle, http client, runtime */ }

#[uniffi::export]
impl RuoCore {
    #[uniffi::constructor]
    pub fn open(db_path: String, key: Vec<u8>) -> Result<std::sync::Arc<Self>, CoreError>;
    pub fn set_session(&self, access_token: String, base_url: String);
    pub fn create_conversation(&self, id: String, title: String, active_language: String, study_mode_default: bool) -> Result<(), CoreError>;
    pub fn save_draft(&self, conversation_id: String, text: String) -> Result<(), CoreError>;
    pub fn get_draft(&self, conversation_id: String) -> Result<Option<String>, CoreError>;
    pub fn read_draft_with_listener(&self, conversation_id: String, listener: std::sync::Arc<dyn DraftReadListener>) -> Result<(), CoreError>;
    pub fn queue_message(&self, req: OutboundRequest) -> Result<LocalMessage, CoreError>;
    pub fn stream_message(&self, req: OutboundRequest, listener: std::sync::Arc<dyn StreamListener>);
    pub fn cancel_stream(&self, message_id: String) -> bool;
    pub fn list_conversations(&self, query: Option<String>) -> Result<Vec<ConversationSummary>, CoreError>;
}
```
The code above is historical Gate 2 spike shape, not the current interface. The Phase 1 v1 interface and its records are specified below.

## Phase 1 interface v1 (Gate 3A approved; Step B implementation)

This Phase 1 interface v1 covers authentication handoff, chat, cached history, drafts, and outbox state only. It exports no upload, audio, or other unimplemented later-phase APIs. The version is frozen for the Step B bridge; compatible additions must use defaulted optional fields, and breaking changes require a new version.

### Ownership, IDs, sync, and retries

Kotlin owns sign-in and refresh-token rotation. Rust holds the access token in memory and owns authenticated HTTP for conversations, messages, history sync, and SSE. Rust never stores or logs tokens or message content. On HTTP 401, Rust reports `UNAUTHENTICATED`; Kotlin refreshes, calls `set_session` again, then retries once using the same client-generated ID. This keeps refresh credentials out of Rust while centralizing SSE parsing, idempotency, and local persistence.

`conversation_id` is generated by the client and is the idempotency key for create; a repeated create by its owner returns the existing row. `client_msg_id` is the send/stream handle everywhere, including `StreamListener` callbacks and `cancel_stream`. It identifies the user's message on the client and is distinct from server-assigned user and assistant `messages.id` values. SSE `meta` reports both server IDs; `done` reports the assistant server ID.

Conversation lists are newest-first keyset pages using `(updated_at, id)`, with both cursor values required together. Timestamps retain full server precision; Rust exposes local cursors as epoch microseconds (`updated_at_us` / `created_at_us`) alongside millisecond display timestamps. Sync requests tombstones and retains server-deleted conversations as deleted records so they do not reappear. On opening a conversation, Rust fetches messages in keyset pages by `(created_at, id)` and maintains only the configured bounded recent offline set. The page sizes and offline bounds are configuration values, not Rust constants. Phase 1 conversation create/edit/delete is server-first and online-only; Phase 5 owns offline edits and last-write-wins.

`sync_history` pulls paged conversations and configured message windows into SQLCipher. Conversation mutations commit the server response locally before notifying listeners. `subscribe_local_changes` reports entity IDs and revisions, never message text; Kotlin reads a snapshot and adapts notifications to `Flow`. Callback notifications avoid polling; a missed notification is recovered by rereading. All callbacks arrive on Rust-owned threads, and Kotlin hops to its selected dispatcher before touching UI state.

Each conversation permits one active local stream; another send in that conversation returns `CONFLICT`. Rust persists the user/outbox row before network work and inserts an assistant placeholder before streaming; deltas update that local row, and it becomes `Sent` only after a successful `done`. The backend persists the completed assistant content before emitting `done`. A retry uses the same `client_msg_id`: a completed response is replayed in full and replaces—not appends to—the partial assistant bubble; an active request returns retryable `STREAM_IN_PROGRESS`; a failed request restarts with the same rows and does not create a duplicate or charge quota again. There is no event cursor or byte-offset continuation. Cancellation returns `true` only for an active handle and reports `CANCELLED`; unknown or completed IDs return `false`.

`CoreError` maps to stable codes: `UNAUTHENTICATED`, `QUOTA_EXCEEDED`, `RATE_LIMITED`, `NETWORK`, `CANCELLED`, `VALIDATION`, `NOT_FOUND`, `CONFLICT`, `KEY_UNAVAILABLE`, `INVALID_KEY`, `WRONG_KEY`, `DATABASE_CORRUPT`, `SCHEMA_TOO_NEW`, and `INTERNAL`. `UNAUTHENTICATED` is not retried by Rust; Kotlin refreshes and retries. `QUOTA_EXCEEDED` is not automatically retried, but includes the retry time. `RATE_LIMITED` is retryable after `retry_after_sec`; `NETWORK` and explicitly transient `INTERNAL` use bounded backoff with the same idempotency key. Cancellation, validation, not-found, conflict, and key/schema errors are not retryable. `CoreError.details` is sanitized diagnostic text only: it must never include message content, tokens, keys, or raw server response bodies. UI maps codes to English/Filipino resources and never renders `details`.

### Key, account, transport, and version policy

`open` creates a database only if the path does not exist and a valid 32-byte key is supplied. Kotlin distinguishes a missing key for an existing database as `KEY_UNAVAILABLE`; SQLCipher rejects a wrong key as `WRONG_KEY`. Corrupt or newer-schema databases return distinct errors without deletion or replacement. Key loss requires a localized warning that reset will delete unsent messages. Only after explicit confirmation does Kotlin close the core, delete the database and sidecars plus the Keystore alias and wrapped key, generate a fresh random key, reopen an empty encrypted database, and re-sync. The database and wrapped-key storage are excluded from cloud backup and device transfer using Android's `dataExtractionRules` (API 31+) and `fullBackupContent` rules (API 30 and lower); see [Android Auto Backup](https://developer.android.com/identity/data/autobackup).

Sign-out and account switch cancel streams, call `clear_session`, close the core and local-change subscriptions, wipe the database/sidecars, Keystore alias and wrapped key, and clear auth state. No account's local cache is retained across sign-out or switching accounts. `clear_session` only drops the in-memory access token.

`set_session` rejects non-HTTPS base URLs in release builds. Cleartext is allowed only for a debug build with the explicit debug flag; release code ignores/rejects that flag. Cached reads/local writes are synchronous database operations and are called off the main thread. Sync and stream entry points return quickly; callbacks run on Rust-owned worker threads. Kotlin's bridge hops callbacks to the selected dispatcher.

Local migrations are numbered, forward-only, and transactional. A core that encounters a newer schema returns `SCHEMA_TOO_NEW` without modification. The interface and local schema each have explicit versions; additive optional record fields use UniFFI defaults so newer Rust can keep older generated bindings source-compatible where supported ([UniFFI 0.32 record defaults](https://mozilla.github.io/uniffi-rs/0.32/proc_macro/records.html)). Breaking ABI changes require a separately versioned object/namespace and matching app release; local schema migrations must preserve every installed app's existing data.

## Threading rules
- `open`, cached reads, and local writes are synchronous database operations; Kotlin calls them on an IO dispatcher, never the main thread.
- Sync and stream entry points return quickly; callbacks run only on Rust-owned worker threads. Kotlin hops to the appropriate dispatcher before touching UI state.

## Key handling
The DB key is passed as raw bytes from Android Keystore. Production builds default to the `sqlcipher` feature, which rejects keys not exactly 32 bytes, applies SQLCipher's raw-key pragma before the first DB read, and probes `sqlite_master` so a wrong key fails before migrations. Rust does not persist the key and clears the owned constructor buffer after opening; zeroize additional temporary buffers where practical.

For host-only logic testing on machines without Perl/OpenSSL build tools, run `cargo test --all --no-default-features --features plain-sqlite-tests` from `core-rust`. This explicitly uses bundled plain SQLite and does not test encryption. Compile-time guards reject this feature on Android and in release builds; do not use it for application data. The Linux CI SQLCipher job runs the full encryption tests separately.

## Error handling
One `CoreError` enum is exported over UniFFI; error payload text is exposed as `details` (not `message`, which collides with Kotlin's `Throwable.message`) alongside a stable code, `retryable` flag, and optional `retry_after_sec`. Stream errors surface through `on_error`; never panic across the FFI boundary.

## Testing
Unit tests: SSE framing, reconnect backoff, outbox transitions, migrations, exact-precision keyset pagination, and SQLCipher key/header behavior. `cargo test --all --no-default-features --features sqlcipher` runs the full encryption suite; `cargo test --all --no-default-features --features plain-sqlite-tests` runs host-only logic tests against plain SQLite. The Gate 2 Android instrumented test passed on API 34 arm64, covering Keystore-wrapped key round-trip, wrong/missing keys, encrypted header, multilingual draft persistence, and a Kotlin callback. Step B adds the mid-stream cancellation FFI test. See [TESTING_EVALS](TESTING_EVALS.md).

## Risk: SQLCipher with OpenSSL on Android
The vendored-OpenSSL SQLCipher build and physical-phone checks passed for the configuration recorded in the accepted [ADR-0010](decisions/ADR-0010-sqlcipher-android-build.md). Do not fall back to unencrypted storage. Phase 1 interface v1 is frozen for Step B; this does not authorize Compose screens.
